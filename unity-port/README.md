## Главное: город не переписан руками, а снят с работающей игры

В `index.html` 409 функций генерации мира. Переводить их вручную —
недели работы и сотни расхождений.

Вместо этого `tools/capture-world.js` **запускает настоящий код игры**
и записывает каждый созданный объект: позицию, поворот, размер, тип
примитива, цвет, свечение. Unity воссоздаёт мир по этим данным.

Это не «похожий» город — это тот же самый, до сантиметра.

```
Захвачено:
  город        7045 мешей, 379 зданий, 372 точки взаимодействия
  ТЦ           1999 мешей на 8 этажах (B5…B1, 1, 2, 3)
  интерьеры    932 меша: дом, офис, магазин, клуб, банк, больница, полиция
```

## Запуск за 5 минут

1. **Unity 6**, шаблон **3D (URP)** или **3D (Built-in)** — работает в обоих,
   шейдер подбирается автоматически.

2. Скопируйте в проект:
   ```
   unity-port/Assets/Scripts          → Assets/Scripts
   unity-port/Assets/StreamingAssets  → Assets/StreamingAssets
   ```

3. Новая пустая сцена → пустой GameObject → скрипт **Bootstrap** → **Play**.

Всё построится само: город, игрок, камера, свет, интерфейс.

## Производительность

7045 объектов по отдельности = 7045 draw call. Телефон бы не выжил.

Что сделано:
- **Склейка мешей** одного материала внутри чанка → **~96 draw call** в кадре
- **Чанки 120 м**, дальние выключаются целиком
- **Коллайдеры только на зданиях** (379 боксов), а не на каждой детали
- Материалы кэшируются: из 7045 мешей — 353 уникальных материала
- На мобильных дальность обзора автоматически меньше

## Подключение к серверу

Сервер переписывать не нужно — Unity подключается к нему как ещё один
клиент, и игроки из браузера и из Unity окажутся в одном мире.

1. Запустите `node server.js`
2. В инспекторе Bootstrap включите `Connect To Server`

Античит уже работает для обоих клиентов. `PlayerController.Teleport()`
сам сообщает серверу о легальных перемещениях — иначе вход в здание
засчитался бы за читерский рывок.

## Честно о состоянии

**Unity в моей песочнице нет — скомпилировать я не мог.** Проверил
статически: баланс скобок, дубли классов, 17 межфайловых обращений,
соответствие всех полей JSON и C#-моделей. Ошибок нет, но **первую
компиляцию делаете вы**. Если что-то не соберётся — пришлите текст
ошибки, поправлю.

### Что упрощено

- **Торы** приближены цилиндрами: у Unity нет примитива-тора.
- **Прохожие выключены по умолчанию.** В веб-версии их убрали намеренно
  ради производительности (в коде так и написано: «НПС ДОЛОЙ НАВСЕГДА»).
  Я перенёс исходные позиции — включаются флагом `Spawn NPCs`
  в инспекторе CityLife.
- **Текстуры** не переносились — в вебе они рисовались на canvas.
  Сейчас всё на цветах материалов.
- **Магазин** показывает первые 60 предметов из 206, чтобы не было
  фриза при открытии. Постраничность добавляется легко.

### Важные детали

**Скорости пересчитаны.** В JS они «на кадр» при 60 FPS
(`position.x += 0.15`), Unity считает в секундах. Экспортёр умножает
на 60: ходьба 9 м/с, бег 16.8. Иначе персонаж полз бы в 60 раз медленнее.

**Свет приглушён намеренно.** В вебе был баг с пересветом — картинка
выцвела добела. Здесь солнце 0.95 и мягкая заливка.

**JsonUtility не читает массив в корне** — поэтому массивы
оборачиваются в `{"items":[...]}` перед разбором.

**StreamingAssets на Android** внутри APK, `File.ReadAllText` не
работает — используется `UnityWebRequest`.
