# FANTAZIA RP — порт на Unity 6

Перенос игры с веб-версии (Three.js) на Unity 6 (6000.0.6f1).

---

## Что уже сделано

| Часть | Статус |
|---|---|
| Данные игры (206 предметов, работы, товары, константы) | экспортированы в JSON |
| Загрузчик данных | `Core/GameData.cs` |
| Контроллер игрока + камера | `Player/PlayerController.cs` |
| Косметика: 24 архетипа, 206 предметов | `Cosmetics/CosmeticBuilder.cs` |
| Сеть к существующему Node-серверу | `Net/NetClient.cs` |

**Важно:** у меня нет Unity в песочнице, скомпилировать я не мог.
Скрипты проверены статически (скобки, ссылки между файлами, соответствие
полей JSON и C#), но первую компиляцию делаете вы. Если что-то не соберётся —
пришлите текст ошибки, поправлю.

## Запуск за 5 минут

1. **Создайте проект** Unity 6, шаблон **3D (URP)** или **3D (Built-in)** —
   код работает и там, и там (шейдер выбирается автоматически).

2. **Скопируйте папки** из `unity-port/` в ваш проект:
   ```
   unity-port/Assets/Scripts          → Assets/Scripts
   unity-port/Assets/StreamingAssets  → Assets/StreamingAssets
   ```

3. **Создайте пустую сцену**, добавьте пустой GameObject,
   назовите `Bootstrap` и повесьте на него скрипт **Bootstrap**.

4. **Нажмите Play.** Появятся земля, свет, игрок и камера.
   Управление: `WASD`, `Shift` — бег, `Space` — прыжок,
   `Ctrl`/`C` — присесть, `V` — вид от первого лица.

5. **Проверьте косметику:** в инспекторе Bootstrap впишите в поле
   `Test Cosmetic` например `crown_god`, `wing_void` или `aura_fire`
   и нажмите Play.

## Подключение к серверу

Веб-сервер **переписывать не нужно** — Unity подключается к нему как ещё
один клиент. Тогда игроки из браузера и из Unity будут в одном мире.

1. Запустите сервер: `node server.js` (из корня репозитория).
2. В инспекторе Bootstrap включите `Connect To Server`.
3. Хост оставьте `localhost`, порт `3000`.

Античит на сервере уже настроен и работает для обоих клиентов.
`PlayerController.Teleport()` сам сообщает серверу о легальных
перемещениях — иначе вход в здание засчитался бы за читерский рывок.

## Обновление данных из веб-версии

Если поменяли косметику или баланс в JS — не переписывайте вручную:

```bash
node unity-port/tools/extract.js
```

Скрипт перечитает `public/fz52-cosmetics.js`, `server.js` и `index.html`
и обновит JSON в `StreamingAssets`.

Проверить C# перед открытием Unity:

```bash
node unity-port/tools/check.js
```

## Что переносится дальше

Порядок по важности:

1. **Город.** Сейчас только плоская земля. Геометрия города в JS
   генерируется процедурно (`public/city2.js`, `newcity.js`) — её можно
   либо экспортировать в JSON так же, как косметику, либо собрать
   заново в редакторе. Второе даст лучший результат.
2. **ТЦ GRAND MALL** — 8 этажей, лифт, эскалаторы. Логика этажей
   уже в `world.json` (высота этажа, названия, координаты лифта).
3. **Модель персонажа.** Сейчас капсула. Косметика цепляется к якорям
   (`HeadAnchor`, `BackAnchor`, `BodyAnchor`, `HandAnchor`) — при замене
   модели достаточно переназначить их в инспекторе.
4. **UI**: инвентарь, магазин, квесты.

## Важные детали, которые легко упустить

**Скорости пересчитаны.** В JS они заданы «на кадр» при 60 FPS
(`position.x += 0.15`), а Unity работает в единицах в секунду.
Экспортёр умножает на 60: ходьба 9 м/с, бег 16.8 м/с. Если взять
исходные числа напрямую, персонаж будет ползти в 60 раз медленнее.

**Свет специально приглушён.** В веб-версии был баг с пересветом —
картинка выцвела добела. В `Bootstrap.BuildLights()` солнце 0.95 и
мягкая заливка. Если поднять ярче, повторится та же засветка.

**Косметика процедурная, а не префабы.** 206 префабов пришлось бы
делать руками и тащить в сборку. Здесь новые предметы добавляются
правкой JSON, Unity открывать не нужно.

**JsonUtility не читает массив в корне.** Поэтому в `GameData.cs`
массивы оборачиваются в `{"items":[...]}` перед разбором. Если будете
добавлять свои JSON — учтите это.

**StreamingAssets на Android** лежит внутри APK, обычным `File.ReadAllText`
не открывается. В `GameData.Read()` для этого случая используется
`UnityWebRequest`.
