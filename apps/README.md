# Windows: файлы для запуска из лаунчера

**Portable ZIP, версия оболочки 1.0.1.** Установщик для этого пакета не нужен.
Распаковать **весь архив**, затем запустить `Fantazia RP 3D.exe` из корня папки.
Лаунчер должен сохранять рядом DLL, `resources`, `locales` и остальные файлы:
одного EXE недостаточно. Рабочую папку процесса установить в папку игры.

```powershell
cd apps
npm ci
npm run windows:portable
```

Workflow `windows-desktop.yml` теперь выдаёт артефакт
`Fantazia-RP-Windows-Portable-x64`. Внутри — игровой клиент ZIP, SHA-256 и
инструкция. Сам ZIP также содержит инструкцию рядом с EXE. Workflow распаковывает
именно готовый архив в папку с пробелами и запускает оттуда приложение.

Это **онлайн-клиент**: игра загружается с выбранного Render/HTTPS-сервера.
Постоянный адрес ещё не подтверждён, поэтому вводится пользователем. Содержимое
v45 и новые игровые обновления этим ZIP не публикуются автоматически. Профиль
клиента остаётся в AppData, поэтому замена папки игры не стирает его.

Android: новый отдельный клиент находится в `android-client/`; инструкции —
`ANDROID-APK-RU.txt`. Workflow собирает TEST APK и, только при настроенных
секретах постоянной подписи, production APK. Проверочный APK не выдаётся
за публичный релиз. ZIP с Windows-файлами на Android не работает. APK требует установки
Android; пакет для запуска внутри лаунчера возможен только при известном
формате и наличии WebView/движка в самом лаунчере. Android-пакет не следует
выдавать за готовый, пока этот формат не определён.

Прежняя команда `npm run windows:build` по-прежнему доступна для NSIS-установщика,
но текущий workflow собирает запрошенный portable ZIP. Справка по устройству
онлайн-клиента и Android-шаблону ниже.

# Fantazia RP — Windows-клиент и отдельный Android-шаблон

## Windows: установщик онлайн-клиента

Версия оболочки **1.0.1**, Windows 10/11 x64. Используется Electron 45.2.1;
содержимое игры загружается с выбранного HTTPS-сервера. Это не перенос
графики на другой движок, не офлайн-сервер и не автоматическая публикация v45.

На первом экране вводится адрес сервера. В релизе **нет заранее заданного
адреса**, токенов или паролей. Node.js игроку не нужен. Оболочка проверяет
`/api/health`, затем открывает отдельное игровое окно. Ошибка сети возвращает
к подключению. F10 — сменить сервер, F11 — полный экран, Ctrl+R — обновить игру.

### Сборка на Windows

На машине разработчика нужен Node.js 22 и доступ к загрузкам npm/GitHub:

```powershell
cd apps
npm ci
npm run check
npm run test:native
npm run windows:build
```

`npm run desktop` запускает оболочку из исходников без обязательной конфигурации
адреса. NSIS-установщик появляется в `apps/release`.

`.github/workflows/windows-desktop.yml` выполняет Windows-проверки изоляции
и собирает portable ZIP; затем проверяет запуск после распаковки, без установки.
Workflow отправляет ZIP и SHA-256 как **артефакт Actions на 14 дней**, не Release
и не развёртывание сайта. Тест NSIS оставлен для отдельной команды установщика. Запускается только для изменений оболочки в текущей
рабочей ветке, либо вручную. Полные инструкции игроку: `INSTALL-WINDOWS-RU.txt`.

Установщик неподписанный: сертификат владельца не предоставлялся. Нельзя
считать предупреждение SmartScreen отсутствующим или отключать проверку TLS.
Сервер игры и физический пользовательский ПК требуют отдельной проверки.

### Хранение и безопасность

- Единственный IPC-мост есть только у локального экрана подключения. Его
  обработчики проверяют отправителя, главный фрейм и точный URL локального файла.
- У удалённой игры нет preload, Node.js или доступа к IPC-мосту; включены sandbox,
  contextIsolation и webSecurity. Междоменные переходы и новые окна блокируются.
- Только HTTPS-домен без credentials/query/hash, путь `/` или `/index.html`.
  Проверка сервера ограничена 15 секундами и 16 КБ ответа; редиректы запрещены.
- Микрофон — только audio-only запрос доверенного игрового окна и явное согласие.
  Камера и устройства запрещены. Скачать можно фото PNG/JPEG/WebP с диалогом,
  автоматического запуска скачанного файла нет.
- Адрес сервера атомарно сохраняется в `server.json` в Electron userData.
  Отдельный persistent-профиль хранит сеанс входа. Удаление приложения не
  стирает эти данные; серверная база в установщик вообще не входит.
- Серверный прогресс v41+ приходит после входа в тот же аккаунт на том же сервере.
  Настройки/несохранённые данные обычного браузера автоматически не переносятся.
- ASAR не скрывает JavaScript и не заменяет серверную проверку прав.

## Android: отдельная исходная заготовка

APK в этой задаче не собирается. Прежний шаблон Capacitor сохранён.
Для Android адрес пока задаётся при конфигурации, а не экраном Windows-клиента:

```powershell
$env:FANTAZIA_GAME_URL = "https://ВАШ-ПОСТОЯННЫЙ-ДОМЕН/"
npm run configure
```

## Android / APK

1. Установить актуальную Android Studio с SDK и JDK, подходящими для
   Capacitor 8. Следовать проверкам Gradle/Android Studio для выбранной версии.
2. Выполнить:

```powershell
npm run android:add
npm run android:sync
npm run android:open
```

`android:add` выполняется один раз и генерирует каталог `apps/android`.
При следующих изменениях достаточно `android:sync`.
3. В Android Studio дождаться Gradle Sync. Для тестирования — Run на
   подключённом устройстве. Для установочного файла — Build APK(s).
4. Для распространения — Generate Signed Bundle / APK, собственный keystore
   и версия приложения. Keystore/пароли не хранить в репозитории или чате.
   Неподписанный debug APK не считать готовым релизом.
5. Проверить WebGL, вход, обе ориентации, системные отступы/клавиатуру,
   джойстик+камеру двумя пальцами, фото/скачивание, возврат после фона и сеть.
   Голосовой чат требует отдельной проверки разрешений WebView/Android;
   при необходимости добавить RECORD_AUDIO и запрос разрешения в native-проект.

Шаблон не блокирует ориентацию. Это WebView-оболочка текущей браузерной игры,
а не отдельный нативный 3D-движок.


Автообновление Electron и публикация в магазинах не настроены. Для обновления
оболочки её нужно пересобрать; содержимое игры обновляется на выбранном сервере.
